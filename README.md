# HITCON Solve Pack: evidence review

A static evidence desk for synthetic practice records. Review a recorded solve, read the actual output, and compare a current file's SHA-256 with its captured hash. The worked report is generated by real local toy solver executions. It is not a submission to HITCON or evidence of organizer acceptance.

## Open locally

From this package, run:

```sh
python3 -m http.server 8973 --bind 127.0.0.1 --directory docs
```

Open http://127.0.0.1:8973/ in your browser. Choose **Open worked example**, then **Check input.json**. The “Get the files for this example” disclosure supplies both the original and changed input. Check the changed file to see a mismatch. Use the run list (native selector on mobile) to inspect ambiguity, exit failure and timeout. Open report file reads only a locally selected, explicitly synthetic schema-v1 report, up to 2 MiB.

File comparison is real browser SHA-256, limited to 16 MiB per file. It checks that one file only. The browser does not run Python, authenticate the report's author, perform a complete replay, or submit flags. Recorded hashes are independently checked against recorded text, establishing internal consistency rather than trustworthy origin. The synthetic marker is an author's declaration, not an automatic detector of private/live material; do not load live contest or private reports here.

## Rebuild the worked report

Python 3.11+ on POSIX is required for the optional local generator. Tested here on Python 3.14.3, macOS ARM64. The generator executes only fixed self-generated fixtures, including deliberate failure and timeout; no third-party challenge code or shell strings. This runner bounds output and time and cleans ordinary process groups; it is not a security sandbox, CPU/memory limit, or containment for escaped children.

```sh
python3 -m solvepack.demo_report
python3 -m unittest discover -s tests -v
node --test tests/*.test.mjs
```

Node 22+ supports the built-in test/runtime APIs. There are no installed dependencies. Reports store UTF-8 text; the fixtures emit ASCII. Arbitrary binary output would need a separate byte-preserving record format before the core CLI can use it.

## Hosting boundary

The `docs/` tree is compatible with GitHub Pages, including project subpaths. If publishing later under `nicholas-afk/hitcon-solve-pack`, configure Pages to serve `docs/` from the chosen branch. No public repository or deployment has been created in this stage. GitHub Pages serves these static files; it does not host a solver, protect API secrets, or run a backend. All assets use relative URLs and system fonts.

No external script/font/service, upload endpoint, browser storage or analytics is used. A content security policy limits requests to the same origin and disallows object content, inline scripts and form submissions. Imported strings render as text. The clean package excludes personal entrant records, credentials and private challenge workspaces. Keep the surrounding project record outside any public repository.
